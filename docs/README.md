# OctoAcme Project Management Documentation

## Overview

OctoAcme follows a **customer-first, iterative project management approach** emphasizing clear ownership, data-informed decisions, and psychological safety. This documentation provides guidance for running all cross-functional projects that deliver product features, services, or integrations.

Our project management philosophy is built on five core principles:
- **Customer-first**: Prioritize customer value and usability in every decision
- **Iterative delivery**: Deliver small, testable increments regularly
- **Clear ownership**: Each project has named Project Manager (PM) and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and continuous improvement

### Project Phases

OctoAcme projects follow a structured five-phase lifecycle:

1. **[Initiation](./octoacme-project-initiation.md)** — Validate business need, align stakeholders, confirm success criteria, and create a lightweight high-level plan
2. **[Planning](./octoacme-project-planning.md)** — Break work into shippable increments, identify dependencies, define Definition of Done, and establish timelines
3. **[Execution & Tracking](./octoacme-execution-and-tracking.md)** — Manage day-to-day execution, maintain quality standards, run regular demos, and escalate blockers
4. **[Release & Deployment](./octoacme-release-and-deployment.md)** — Standardize release processes, manage pre-release requirements, and reduce deployment risk
5. **[Retrospective & Improvement](./octoacme-retrospective-and-continuous-improvement.md)** — Capture learnings, identify improvements, and convert action items into backlog work

## Quick Reference

### Key Roles
- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs, approvals, and guidance

### Communication Cadence
- **Weekly PM + PdM sync** — Alignment on priorities, risks, and blockers
- **Twice-weekly delivery team standups** — Progress, blockers, dependencies (or as agreed)
- **Monthly stakeholder updates** — High-level status and milestones
- **Ad-hoc escalations** — Critical issues and decisions

### Key Artifacts
- Project Charter / One-pager
- Roadmap and Release Plan
- Sprint/Iteration Backlog
- Acceptance Criteria & Definition of Done
- Risk Register
- Retrospective notes and action items
